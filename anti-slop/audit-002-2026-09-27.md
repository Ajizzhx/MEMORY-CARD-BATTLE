## Detailed Findings

### [F-010] R-26: Missing `prefers-reduced-motion` Media Query
- **Rule:** R-26 & `antislop-human` (Motion Sensitivity — "Respect `prefers-reduced-motion: reduce`. Animations and transitions must be zeroed out or reduced to instant fades for users with vestibular disorders")
- **Tier:** Hard Gate (HIGH)
- **Affected Files:**
  - `src/index.css`
- **Root Cause:** Keyframe animations (`screen-shake`, `hpPulseDanger`, `spin`, modal zoom transitions) lack a reduced-motion fallback.
- **Proposed Solution:** Add a global `@media (prefers-reduced-motion: reduce)` block in `src/index.css` that disables continuous animations and replaces motion transitions with instant cuts.

---

### [F-011] R-29 / R-32: Dialog Modals Lack ARIA Roles and Labels
- **Rule:** R-29 & R-32 (Dialog Accessibility — "Every modal overlay must be identifiable to assistive technologies via `role="dialog"` or `role="alertdialog"`, `aria-modal="true"`, and `aria-labelledby`")
- **Tier:** Hard Gate (HIGH)
- **Affected Files:**
  - `src/components/LeaderboardModal/LeaderboardModal.jsx`
  - `src/components/CatalogModal/CatalogModal.jsx`
  - `src/components/GuideModal/GuideModal.jsx`
  - `src/components/LogModal/LogModal.jsx`
  - `src/components/PauseModal/PauseModal.jsx`
  - `src/components/ResetConfirmModal/ResetConfirmModal.jsx`
  - `src/components/CardDetailModal/CardDetailModal.jsx`
  - `src/components/LootModal/LootModal.jsx`
  - `src/components/GameOverModal/GameOverModal.jsx`
  - `src/components/NameModal/NameModal.jsx`
- **Root Cause:** All dialog contents are rendered as plain `<div>` containers. Screen readers cannot tell users that focus has entered a distinct modal dialog.
- **Proposed Solution:** Add `role="dialog"` (and `role="alertdialog"` for `ResetConfirmModal`), `aria-modal="true"`, and `aria-labelledby` pointing to the modal's primary heading `id`.

---

### [F-012] R-24 / R-29: Input Field in NameModal Lacks Accessible Name
- **Rule:** R-24 & R-29 (Form Controls — "Every input element must have a clear programmatic accessible name via `<label>` or `aria-label`")
- **Tier:** Hard Gate (HIGH)
- **Affected Files:**
  - `src/components/NameModal/NameModal.jsx`
- **Root Cause:** `<input className="name-input-field" ...>` uses only `placeholder`. WCAG 4.1.2 mandates that placeholders cannot substitute for an accessible name.
- **Proposed Solution:** Add `aria-label={t('nameInputPlaceholder', currentLang)}` and `id="player-name-input"` to the input.

---

### [F-013] R-29: Modal Close Icon Buttons Lack Explicit `aria-label`
- **Rule:** R-29 (Accessible Icon Buttons — "Buttons containing only icons or single glyphs must provide an accessible name via `aria-label`")
- **Tier:** Hard Gate (HIGH)
- **Affected Files:**
  - `src/components/LeaderboardModal/LeaderboardModal.jsx`
  - `src/components/CatalogModal/CatalogModal.jsx`
  - `src/components/GuideModal/GuideModal.jsx`
  - `src/components/PauseModal/PauseModal.jsx`
  - `src/components/CardDetailModal/CardDetailModal.jsx`
- **Root Cause:** Buttons render only `✕`. Screen readers announce "multiplication sign" or uninformative character names.
- **Proposed Solution:** Add `aria-label={t('closeCatalogBtn', currentLang) || "Tutup"}` to all `.modal-close-icon-btn` elements.

---

### [F-014] R-29 / R-32: Tabs in LeaderboardModal Lack ARIA Tab Semantics
- **Rule:** R-29 & R-32 (WAI-ARIA Tabs Pattern — "Tab containers require `role="tablist"` and tabs require `role="tab"` with `aria-selected`")
- **Tier:** Purpose-Gate (MEDIUM)
- **Affected Files:**
  - `src/components/LeaderboardModal/LeaderboardModal.jsx`
- **Root Cause:** Tab buttons are plain `<button>` elements inside a regular `<div>` without semantic relationship.
- **Proposed Solution:** Add `role="tablist"` on `.lb-tabs` and `role="tab"`, `aria-selected={activeTab === '...'}` on the buttons.

---

### [F-015] R-29: Main Application Container Lacks Landmark Semantics
- **Rule:** R-29 (Semantic HTML Landmarks — "Core content belongs in a `<main>` element")
- **Tier:** Quality Locks (LOW)
- **Affected Files:**
  - `src/components/GameBoard/GameBoard.jsx`
- **Root Cause:** Outermost wrapper is `<div className="game-board-container ...">`.
- **Proposed Solution:** Change wrapper from `<div>` to `<main>` (or add `role="main"`).

---

### [F-016] R-38: Missing Meta Description in `index.html`
- **Rule:** R-38 & Web Guidelines (HTML Meta & SEO — "Every page requires a concise, accurate meta description")
- **Tier:** Quality Locks (LOW)
- **Affected Files:**
  - `index.html`
- **Root Cause:** `index.html` specifies `<title>` but omits `<meta name="description">`.
- **Proposed Solution:** Add `<meta name="description" content="Memory Card Battle - Cyberfantasy RPG & Memory Matching Game featuring tactical 1v1 battle mechanics, 21 unique cyber cards, and boss challenge.">`.
